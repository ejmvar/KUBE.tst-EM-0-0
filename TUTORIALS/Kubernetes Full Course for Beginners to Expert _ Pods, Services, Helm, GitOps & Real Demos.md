### Lesson 58: The Pod Network

**2:21:35** · In this lesson, you will learn the rules and see them working. Kubernetes demands three things from the network. Every pod gets its own IP address. **2:22:37** · The plugin then makes sure packets find their way between nodes using tunnels or routes. Popular plugins are Calico, Cillium, and Flannel.

### Lesson 74: Lab: Owners and Garbage

### Lesson 78: Lab: Graceful Shutdown

**3:07:23** · The last piece.

**3:07:25** · When Kubernetes stops a pod during an update or a scale down, it first asks the application to stop politely. If the application ignores the request, Kubernetes waits and then kills it. A well-behaved application listens, finishes its current work, and exits. Let's watch both behaviors and measure the difference. Here is the sequence. Kubernetes marks the pod as terminating and removes it from the service. So, no new requests arrive. If a pre-stop hook exists, it runs.

**3:08:02** · Then the container receives the term signal, which means please stop. The application now has a grace period, 30 seconds by default, to finish in-flight requests, close connections, and exit. If it is still running when the time is up, Kubernetes sends a kill signal, which cannot be ignored. Apps that handle the term signal restart quickly and lose no work. Here are two pods. Both have a grace period of 8 seconds, shortened for this lab.

**3:08:36** · The first just sleeps and ignores the stop request. The second runs a small shell script, which traps the term signal. When the signal arrives, it prints a message and exits cleanly. **3:08:59** · Let's measure.
